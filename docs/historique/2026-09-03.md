## 07:00 — Réalisé : le hook d'historisation cesse de bloquer git

**Demande :** corriger le hook pour qu'il ne bloque plus les rebases.

**Actions :**
- Diagnostic posé la veille au soir confirmé et élargi : en écrivant dans
  `docs/historique/<jour>.md` à chaque prompt, le hook laissait un fichier
  **suivi** modifié en permanence. Git s'y oppose à trois endroits — `rebase` et
  `pull --rebase` refusent de démarrer, `rebase --continue` refuse de poursuivre
  (message trompeur « You must edit all merge conflicts », qui vient en réalité
  de `has_unstaged_changes` dans `builtin/rebase.c`), et `merge` refuse dès que
  la fusion toucherait le fichier. Le hook rendait donc bloquante chaque
  opération git du dépôt qu'il était censé documenter.
- `historiser-prompt.py` réécrit : il empile désormais les demandes dans un
  tampon hors dépôt (`~/.local/state/historiser/<dépôt>.jsonl`, un fichier par
  dépôt) au lieu d'écrire dans l'arbre de travail. Les garde-fous d'origine sont
  conservés — périmètre `HISTORISER_RACINE`, silence total, sortie 0 quoi qu'il
  arrive, anti-doublon (qui regarde maintenant le tampon *et* le journal).
- `historiser-flush.py` ajouté : verse le tampon dans les journaux datés, en
  préservant l'horodatage de capture et l'ordre. Le tampon est renommé avant
  versement, si bien qu'un prompt arrivant pendant la vidange ouvre un tampon
  neuf au lieu d'être effacé avec l'ancien ; un versement interrompu se rejoue
  sans doubler les entrées. `--montrer` liste sans consommer.
- Testé sur un dépôt jetable, sur le scénario exact qui avait échoué le matin :
  arbre propre après deux prompts, `rebase --continue` réussi avec une demande
  capturée **pendant** le conflit, vidange correcte puis idempotente,
  anti-doublon des deux côtés, silence hors périmètre.

**Fichiers :**
